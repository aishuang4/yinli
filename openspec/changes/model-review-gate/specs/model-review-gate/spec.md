# Spec Delta

## Purpose

用一次小型模型判定代替关键词，决定一轮已完成的工作要不要进入技能自进化；同一套判定契约可供以后的语义门复用。

## ADDED Requirements

### Requirement: 语义审核与确定性短路分开

系统 MUST 把「能不能调用模型」和「语义上放不放行」分开。空回合、未成功完成的 Run、疑似敏感内容、以及非手动的寒暄，MUST 由规则直接拒绝，且 MUST NOT 调用模型审核。用户显式要求把前序工作做成技能时，MUST 直接放行，且 MUST NOT 再经过模型审核。

#### Scenario: 敏感内容不调用模型

- **WHEN** 一轮已完成对话的用户句或最终回覆含有疑似密钥或口令
- **THEN** 技能自进化被拒绝
- **THEN** 系统不发起模型审核调用

#### Scenario: 手动请求直接放行

- **WHEN** 用户显式要求把上一轮完成的工作生成技能，且上一轮有用户句和最终回覆
- **THEN** 技能自进化进入草稿生成
- **THEN** 系统不发起模型审核调用

### Requirement: 审核发生在成功回合落库之后

系统 MUST 在 Leader 或 Team 成功收尾、助手消息已经写入之后，于后台任务中发起技能触发审核。用户可见回复 MUST NOT 等待这次审核。失败收尾 MUST NOT 发起模型审核。同一成功回合 MUST 只审核一次，MUST NOT 按工具调用次数累计后再审。

#### Scenario: 成功收尾后后台审核

- **WHEN** 一轮对话成功结束且助手消息已落库
- **THEN** 系统在后台判断是否进入技能草稿生成
- **THEN** 该判断不阻塞已经返回的回复

#### Scenario: 失败回合不审核

- **WHEN** 一轮对话以失败收尾
- **THEN** 系统不发起模型审核

### Requirement: 审核上下文使用压缩后的会话

模型审核的上下文 MUST 在成功收尾时从当前 Agent 的会话状态拷贝，并按这个顺序组装：已有的压缩摘要、压缩后仍留在上下文中的近期消息、本轮已完成技能的标识和名称、固定的审核标准。没有发生压缩时，摘要段 MUST 省略，近期消息就是当时还在上下文里的内容。它 MUST NOT 从持久化的全部聊天记录重放被摘要替换掉的原文。它 MUST NOT 包含思考过程、技能正文、习惯或专业区记忆。审核标准 MUST 采用 Hermes 技能审里关于「什么算可复用技能、什么不能写成经验」的判断，MUST NOT 指示模型调用技能写入工具或直接修改技能文件。模型 MUST 只返回是否放行、信心和理由。这份拷贝 MUST 在后台任务开始前完成，后续回合对同一 Agent 上下文的修改 MUST NOT 改到这次审核。

#### Scenario: 长对话已压缩

- **WHEN** 一轮成功对话的上下文已经被压成摘要加近期消息
- **THEN** 审核看得到该摘要和近期消息
- **THEN** 审核看不到已被摘要替换的更早原文

#### Scenario: 上下文不含技能正文

- **WHEN** 本轮使用过一个已安装技能并成功结束
- **THEN** 审核看得到该技能的名称
- **THEN** 审核看不到该技能的说明书正文

### Requirement: 技能自进化的自动触发由模型审核决定

对通过确定性短路、且不是手动请求的成功回合，系统 MUST 调用模型审核判断是否进入技能草稿生成。该判断 MUST 依据压缩摘要（若有）、压缩后仍留在上下文中的近期消息，以及本轮已完成技能的名称，MUST NOT 要求正文命中固定关键词列表。模型放行时，系统 MUST 进入现有技能草稿生成；模型拒绝时，系统 MUST NOT 生成技能草稿。关键词规则 MUST NOT 在模型已给出有效判定后再否决该判定。

#### Scenario: 没有关键词但模型放行

- **WHEN** 一轮成功对话没有命中现行可复用关键词，工具链摘要显示完成了一段可重复流程，且模型审核放行
- **THEN** 系统进入技能草稿生成

#### Scenario: 模型拒绝

- **WHEN** 一轮成功对话通过确定性短路，模型审核拒绝并给出理由
- **THEN** 系统不生成技能草稿
- **THEN** 拒绝理由被保留在该轮技能自进化记录中

### Requirement: 模型失败时回退到现行规则

模型审核超时、调用失败或输出无法解析时，系统 MUST 回退到现行关键词触发规则，并 MUST 在记录中标明这一轮使用了规则回退。回退结果 MUST 仍然遵守确定性短路。多层记忆的习惯、专业区和时间线写入 MUST 不受这次回退影响。

#### Scenario: 模型不可用

- **WHEN** 一轮本应接受模型审核，但模型调用失败
- **THEN** 系统改用现行关键词规则决定是否进入技能草稿生成
- **THEN** 记录标明判定来源是规则回退

### Requirement: 审核门可被其他语义门复用

模型审核 MUST 暴露稳定的请求和判定：用途、待判断的问题、证据、放行标准、拒绝标准；判定包含是否放行、理由、信心和来源（模型、规则或回退）。它 MUST NOT 写入技能、记忆或文件。本变更 MUST 只把技能自进化自动触发接到这个门上；其他业务门 MUST 保持原样，直到各自的变更显式接入。

#### Scenario: 判定不产生副作用

- **WHEN** 系统为技能自进化发起一次模型审核
- **THEN** 判定结果只决定是否继续草稿生成
- **THEN** 审核本身不注册技能、不改记忆文件
