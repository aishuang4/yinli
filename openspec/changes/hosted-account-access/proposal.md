# Proposal

## Why

桌面安装包还卡在 macOS 公证和 Windows 签名上，现在又不能把无鉴权的本机后端直接放到公网：反向代理看起来像回环地址，会绕过现有的本机访问限制。需要一条可注册的 Web 服务，同时让桌面端继续离线可用；登录只负责领取平台统一提供的模型，本机数据仍留在本机。

## What Changes

- Web 托管要求邮箱注册、验证后登录。未登录不能使用托管工作台。密码只存哈希，会话用 Cookie。
- 增加管理员端：查看用户、在线或离线、Web / 桌面来源，以及停用和恢复账号。管理员由环境变量指定，公开注册不能把自己变成管理员。
- Web 上的 Workspace、Project、对话、群聊、定时任务、习惯记忆和上传文件按登录用户隔离。模型 Key 留在部署级目录，只有管理员可写。
- 桌面端可以不登录使用，数据继续存在本机。未登录只用本机 `models.json`。登录后额外看到平台模型，本机后端把该轮请求转到服务器模型网关，Key 不下发到电脑。
- 退出登录、会话过期或账号停用后，桌面端平台模型消失，本机模型和本机数据仍可使用。Web 与桌面不互相同步会话和文件。
- 托管模式未带有效会话时，现有工作台 API 拒绝访问。桌面本机回环 API 仍不强制登录。

## Capabilities

### New Capabilities

- `account-access`：邮箱注册、验证、登录、退出、重置密码，以及托管模式与桌面本机模式的访问边界。
- `admin-users`：管理员查看用户列表、在线状态和客户端类型，并停用或恢复账号。
- `hosted-user-data`：Web 托管下工作台数据按账号隔离，普通用户不能改部署级模型 Key。
- `platform-models`：平台模型目录与调用网关；桌面端登录后领取模型且不改写本机 `models.json`。

### Modified Capabilities

- （无。`group-studio` 与 `skills` 的现有要求不变。托管模式只是在调用这些 API 之前先要求会话。）

## Impact

- 后端：新增账号、会话、验证码存储；`hosted` 请求校验会话；管理员接口；按 `user_id` 限定 Web 数据；平台模型目录与流式调用网关。新增密码哈希依赖。
- 前端：Web 的注册、验证、登录和未登录拦截；管理员页；桌面端可选登录、服务地址，以及模型选择器中的平台分组。
- 桌面端：本机保存托管会话令牌。Chat、文件和记忆路径仍在本机数据目录。
- 部署：反向代理只发布 HTTPS，`8765` 不映射到公网；SMTP 用于验证码和重置密码。
- 文档：实现时同步 `docs/web-service-plan.md` 已记录的决定；落地后再写入 `AGENTS.md` 与架构总览。本提案不改 Chat SSE 和群聊事件字段。
